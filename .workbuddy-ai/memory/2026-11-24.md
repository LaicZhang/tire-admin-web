## 补充（同日）：修复 .css 未生效 + .vue SCSS 规则上提

### 1. Node 版本疑问的答案

WorkBuddy 沙箱运行时会在 PATH 最前面注入 `~/.workbuddy-ai/binaries/node/versions/22.22.2-6/bin`（重复出现 3+ 次），把 `/usr/local/bin/node`（v26.13.0，官方 pkg 安装）挤到后面。用户自己的 `~/.zshrc` 里 nvm 是注释掉的，没有 node 相关 PATH。`/usr/local/bin/pnpm` 是 corepack shim（`COREPACK_ENABLE_DOWNLOAD_PROMPT??='1'`），所以直接用它会被交互提示卡住；真实 pnpm 在 `~/Library/pnpm/bin/pnpm`。**结论：这是 agent 运行时作用域的问题，不是机器级配置**。

### 2. `.css` 之前完全没被 lint

`stylelint.config.js` 的 override `files: ["**/*.(css|html|vue)"]` 给 `.css` 也套了 `postcss-html`，纯 CSS 被当 HTML 解析 → 零节点。改为 `["**/*.{html,vue}"]` 后 `.css` 走默认 CSS 解析器，立刻暴露 103 条告警。

处理：

- `--fix` 自动修 60+ 条（`order/properties-order`、`::before` 双冒号、`rgba`→`rgb(...)` 现代写法、`grid-gap`→`gap`、`max-width`→`width <=` MQ4 等）。项目本来就全用 MQ4 range 写法，所以对齐而非引入新语法。
- `at-rule-no-unknown` 补 Tailwind v4 指令：`theme`/`utility`/`custom-variant`/`source`/`plugin`/`config`/`reference`。
- 新增 `at-rule-prelude-no-invalid` 显式配置，ignoreAtRules 含 Tailwind 指令 + Sass 指令（`mixin`/`include`/`if`/`each`/`use`…），保留默认的 `media`。注意：仓库级 `rules` 会覆盖 recommended-scss 的 `null`，所以必须自己列全 Sass 指令，否则 `@mixin xxx($a)` 会误报。
- `src/style/tailwind.css` 单独 override：`import-notation: "string"`（v4 要求字符串形式 import）、`custom-property-pattern: null`（`--color-bg_color` 对应工具类名）。
- `.stylelintignore` 增加 `src/assets/iconfont/iconfont.css`（iconfont.cn 生成，重新生成会覆盖）。

### 3. `.vue` 的 SCSS 规则上提

把 `stylelint-config-recommended-vue/scss/index.js` 从 `*.scss` 的 override 提到顶层 `extends`，`.vue` 的 `<style lang="scss">` 终于受 `scss/*` 规则约束（16 条）。仓库自带 override 仍然最后应用，`customSyntax` 保持 `postcss-html`（已验证）。

暴露 47 条 `scss/at-extend-no-missing-placeholder`，全部形如 `.page-container { @extend .page-container; }` 的**自引用**。用 sass 编译验证：有无这行产物完全一致（纯 no-op），且 `.page-container`/`.search-form` 在 `src/style/reset.scss` 已有全局定义。→ 删除 47 个块，其中 20 个文件删完 style 块变空，连 `<style scoped lang="scss">` 一起移除（避免 `no-empty-source`）。共改 34 个 .vue。
